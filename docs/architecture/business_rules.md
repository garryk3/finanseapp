# Канонические бизнес-правила FinanseApp

Этот документ — единый источник поведения. Задачи в `PLAN.md` ссылаются на ID правил;
изменение поведения начинается с изменения соответствующего правила и его тестов.

## 1. Приоритет источников и разрешённые конфликты

| Тема | Решение | Причина |
|---|---|---|
| Курс и пересчёт | `rateToRub` — RUB за 1 единицу валюты; умножение | Основной Markdown BR-T-2/BR-IE-2; деление из PDF отклонено |
| Обязательства и цели погашения долга | Не входят в скоуп | Прямое исключение основного Markdown |
| Красный для расходов | Запрещён; `error` только для ошибок/разрушения | `DESIGN.md` и доступность |
| Управление активами | Основной раздел «Активы», настройки содержат только справочники | Карта экранов Markdown; PDF не требует дублировать CRUD в настройках |
| Цели | Только счета/инвестиции, явная привязка активов | BR-G-1…3 и T-601; долговые цели PDF исключены |
| Квартира | `name` + опциональный `address`, а не адрес вместо названия | Совмещение BR-A-4 и PDF без потери пользовательского имени |
| Отрицательный баланс | Запрещён | Подтверждено владельцем; согласуется со строгой валидацией PDF |
| Капитализация | Ежемесячная | Подтверждено владельцем; `n = 12` из PDF |
| Базовая валюта | Выбирается; RUB остаётся каноническим audit snapshot | Подтверждено владельцем, BR-C-5 и T-103 |

## 2. Общие инварианты

- **BR-VAL-1.** Денежная сумма хранится как целое `minorUnits`; ввод парсится в
  `Decimal`, затем округляется до минорной единицы. Бинарный `double` не участвует в
  учётных итогах.
- **BR-VAL-2.** Дата операции — `LocalDate` без timezone; в БД — `yyyy-MM-dd`. Дата
  создания/изменения записи — UTC `DateTime`.
- **BR-VAL-3.** Названия после `trim` непустые; сравнение уникальности справочников —
  без учёта регистра и с нормализацией пробелов.
- **BR-VAL-4.** Любой курс строго больше нуля. Для RUB используется фиксированный 1,
  сетевой запрос не выполняется.
- **BR-VAL-5.** Дата дохода, расхода, транзакции и оценки не может быть в будущем.
- **BR-VAL-6.** Годовая ставка счёта находится в диапазоне `[0; 100]`; `startDate <=
  endDate`, если дата окончания указана.
- **BR-VAL-7.** Повторное нажатие Save блокируется до завершения записи. Ошибка
  сохранения не показывает ложный успех и не закрывает форму.
- **BR-VAL-8.** Изменение валюты актива запрещено после появления операций или оценок.

## 3. Транзакции активов (BR-T)

- **BR-T-1.** Запись хранит актив, положительную исходную сумму, исходную валюту,
  `occurredOn`, `rateToRub`, рассчитанный `amountRubMinor`, комментарий и вид операции.
- **BR-T-2.** `amountRub = amountOriginal × rateToRub`; знак итогового влияния задаёт
  вид операции, а не отрицательный ввод суммы.
- **BR-T-3.** Редактирование добавляет полный immutable snapshot в revisions и обновляет
  current projection в той же DB-транзакции. Прежняя ревизия не изменяется.
- **BR-T-4.** Удаление мягкое: новая ревизия имеет `deletedAt`; строка и история не
  удаляются физически.
- **BR-T-5.** Исходная сумма строго больше нуля.
- **BR-T-6.** `occurredOn <= today`.
- **BR-T-7.** Комментарий необязателен; пустая строка нормализуется в `null`.
- **BR-T-8.** Виды: `deposit`, `withdrawal`, `transferOut`, `transferIn`. Перевод имеет
  две связанные ноги в `asset_transfers`; обе создаются/редактируются/удаляются атомарно.
- **BR-T-9.** Перевод не создаёт запись денежного потока. Изменение одной ноги без
  синхронизации второй запрещено; редактирование доступно через форму перевода.
- **BR-T-10.** Транзакции разрешены только счетам и инвестициям. Для квартиры есть
  денежный поток и оценки, но не транзакции стоимости.

## 4. Валюты и курсы (BR-C)

- **BR-C-1.** Курс запрашивается на `occurredOn` и сохраняется вместе с операцией.
  Используется ЦБ РФ `XML_daily.asp`; `rateToRub = Value / Nominal`.
- **BR-C-2.** Если курс на точную дату отсутствует, сеть недоступна или ответ относится
  к другой дате, сохранение ждёт ручного положительного курса либо другой даты.
  Ближайший прошлый/текущий курс молча не подставляется.
- **BR-C-3.** Курс, связанный хотя бы с одной операцией или оценкой, неизменяем.
  Ручной сохранённый курс не перезаписывается последующим ответом ЦБ.
- **BR-C-4.** Валюту нельзя удалить/отключить, если она используется активами,
  операциями, оценками, целями либо выбрана базовой. RUB не удаляется и не отключается.
- **BR-C-5.** По умолчанию базовая валюта RUB. При выборе другой базовой валюты итоги
  пересчитываются через RUB по курсам соответствующей даты; audit snapshots не меняются.
- **BR-C-6.** Детальный экран актива показывает исходную сумму и эквивалент в выбранной
  базовой валюте. Переключатель не изменяет хранимые данные.
- **BR-C-7.** Кэш курса уникален по `(currencyCode, date)` и содержит источник
  `cbr|manual` и `fetchedAt`. Кэш доступен offline.
- **BR-C-8.** Пользовательская валюта имеет трёхбуквенный uppercase ISO-like код,
  название и `fractionDigits`; пять предустановленных валют создаются seed.

## 5. Активы (BR-A)

- **BR-A-1.** Счёт хранит название, банк, валюту, начальный баланс, ставку, дату начала
  и опциональную дату окончания. Текущий баланс вычисляется, а не редактируется как
  независимый факт.
- **BR-A-2.** Прогноз вклада использует ежемесячную капитализацию и календарный
  неполный месяц из `calculations.md`; пересчитывается после операций.
- **BR-A-3.** Инвестиция хранит название, брокера, валюту и начальную стоимость.
  Текущая стоимость — последняя абсолютная оценка плюс более поздние операции; до
  первой оценки — начальная стоимость плюс все операции.
- **BR-A-4.** Квартира хранит название, опциональный адрес, валюту, начальную/текущую
  рыночную стоимость через оценки и опциональную цену покупки.
- **BR-A-5.** Актив без связей можно физически удалить после подтверждения. Актив со
  связанными операциями, оценками, целями или денежным потоком можно только
  архивировать; диалог показывает виды и количество связей.
- **BR-A-6.** Архивный актив скрыт из новых выборов и текущих итогов начиная с даты
  архивирования, но его история и прошлые точки графика сохраняются. Цель с архивным
  активом сохраняет связь и явно помечает актив архивным.
- **BR-A-7.** Оценка инвестиции/квартиры — отдельная абсолютная запись на дату. Она не
  является доходом, расходом или транзакцией пополнения/списания.

## 6. Подгруппы банков и брокеров (BR-P)

- **BR-P-1…2.** Пользователь создаёт и переименовывает банки и брокеры; типы не
  смешиваются даже при одинаковых названиях.
- **BR-P-3.** Занятую подгруппу нельзя удалить. Свободную можно удалить после
  подтверждения.
- **BR-P-4.** Диалог занятой подгруппы содержит число активов и действие «Перенести в
  другую подгруппу того же типа» либо «Отмена». Перенос всех активов и удаление исходной
  подгруппы выполняются одной DB-транзакцией.
- **BR-P-5.** Подгруппа обязательна для счёта/инвестиции и недоступна для квартиры.

## 7. Цели (BR-G)

- **BR-G-1.** Категория цели только `accounts` или `investments`; связанные активы должны
  иметь тот же тип.
- **BR-G-2.** Математическая разница `target − progress`; отображаемый дефицит
  `max(0, target − progress)`, превышение `max(0, progress − target)`.
- **BR-G-3.** Прогресс автоматически равен сумме текущих стоимостей выбранных активов,
  пересчитанных в валюту цели на сегодня. Ручных взносов к прогрессу нет.
- **BR-G-4.** Если есть будущая/текущая `targetDate` и дефицит >0, рекомендация —
  `deficit / calendarMonthsRemaining`. Отсутствие даты даёт `null`; просроченная цель
  показывает отставание без деления на ноль.
- **BR-G-5.** Статусы: `active`, `achieved`, `closed`. `active ↔ achieved` происходит
  автоматически по `progress >= target`; `closed` меняется только вручную и не получает
  автоматических переходов.
- **BR-G-6.** Цель имеет название, положительную целевую сумму и валюту (по умолчанию
  текущая базовая), опциональную дату не в прошлом при создании и минимум один актив.
- **BR-G-7.** Удаление цели мягкое и не меняет активы/операции. Связи остаются в БД для
  истории, но удалённая цель скрыта из обычных списков.

## 8. Итоги и история (BR-S)

- **BR-S-1.** Чистый капитал — сумма текущих стоимостей всех неархивных активов в
  выбранной базовой валюте; обязательства не вычитаются, поскольку вне скоупа.
- **BR-S-2.** Создание, редактирование и удаление транзакций/денежного потока хранятся в
  revisions; аудит показывает время изменения, автора-устройство не требуется, тип
  действия, предыдущую и новую версию.
- **BR-S-3.** График стоимости строит точки `LocalDate → сумма активов в базовой валюте`.
  Для каждой даты используются состояния активов и курсы на эту дату, а не текущий курс.
- **BR-S-4.** Обычные журналы скрывают удалённые записи. Аудит доступен из «Ещё» и
  показывает удалённые и прежние ревизии без возможности незаметного изменения.
- **BR-S-5.** Все экраны итогов используют один analytics use case; независимые формулы
  в ViewModel запрещены.

## 9. Доходы и расходы (BR-IE)

- **BR-IE-1.** `CashflowEntry` хранит тип, категорию, положительную сумму, валюту,
  `occurredOn`, курс, RUB snapshot, комментарий, опциональные `propertyId` и `accountId`,
  `affectsBalance` и опциональный `assetTransactionId`.
- **BR-IE-2.** `amountRub = amountOriginal × rateToRub` с теми же правилами точности.
- **BR-IE-3.** Внутренние переводы не создают и не участвуют в денежном потоке.
- **BR-IE-4.** Переоценка инвестиции/квартиры не создаёт доход/расход.
- **BR-IE-5.** Запись без счёта участвует только в денежном потоке и не меняет активы.
- **BR-IE-6.** Если выбран счёт и `affectsBalance = true`, создаётся связанная
  транзакция: доход → `deposit`, расход → `withdrawal`. Иначе транзакции нет.
- **BR-IE-7.** Источник cashflow-итогов — только `CashflowEntry`. Связанная транзакция
  влияет только на баланс и не создаёт вторую запись денежного потока.
- **BR-IE-8.** Обычная транзакция актива без явной классификации не участвует в
  денежном потоке.
- **BR-IE-9.** При классификации транзакции счёта как дохода/расхода создаётся связанный
  `CashflowEntry`; та же атомарная команда используется в обоих направлениях форм.
- **BR-IE-10.** Сумма строго >0; знак итога определяется типом.
- **BR-IE-11.** `occurredOn <= today`.
- **BR-IE-12.** Периодические итоги используют `occurredOn`, а не `createdAt`.
- **BR-IE-13.** Денежный поток не меняет чистый капитал напрямую. Влияние возможно только
  через связанную транзакцию актива.
- **BR-IE-14.** Мягкое удаление записи с `assetTransactionId` в той же DB-транзакции
  мягко удаляет связанную транзакцию; обе получают новые ревизии.
- **BR-IE-15.** Редактирование создаёт новую ревизию. При изменении даты/валюты курс
  запрашивается заново; связанная транзакция синхронно получает новую ревизию.
- **BR-IE-16.** `affectsBalance = true` требует `accountId`. При отключении опции или
  удалении счёта из формы существующая связанная транзакция мягко удаляется; повторное
  включение создаёт новую связанную транзакцию, старая остаётся в аудите.
- **BR-IE-17.** Связанный расход и снятие через классификацию проверяют запрет
  отрицательного баланса до commit; при нарушении откатываются обе записи.

## 10. Недвижимость и денежный поток (BR-RE)

- **BR-RE-1…2.** Доход/расход можно создать из квартиры; такая запись обязана сохранить
  `propertyId` именно на квартиру.
- **BR-RE-3.** Операции квартиры входят в общие cashflow-итоги без дополнительного
  коэффициента или второй записи.
- **BR-RE-4.** Содержание, коммунальные платежи, ремонт и налоги не меняют рыночную
  стоимость автоматически.
- **BR-RE-5.** Детали квартиры показывают доходы, расходы, чистый поток и операции за
  выбранный период: месяц, год, всё время, произвольный диапазон.
- **BR-RE-6.** Валовая/чистая доходность — P2, за последние 12 месяцев, с пояснением
  оценочности; нулевая текущая стоимость даёт `null`.
- **BR-RE-7.** «Аренда» как доход и «Аренда жилья» как расход — разные категории и
  противоположные типы денежного потока.

## 11. Категории (BR-CAT)

- **BR-CAT-1…3.** Категория имеет тип, название, опциональные `colorKey`/`iconKey`,
  `isPreset` и `archivedAt`. Цвет/иконка выбираются только из семантических ключей UIKit.
- **BR-CAT-4.** Используемая категория физически не удаляется. Пользователь может
  архивировать её или перенести все операции в активную категорию того же типа одной
  DB-транзакцией, после чего удалить свободную исходную категорию.
- **BR-CAT-5.** Уникальность имени действует внутри типа среди неархивных категорий;
  одинаковые названия дохода и расхода разрешены.
- **BR-CAT-6.** Предустановленные категории редактируются и удаляются по общим правилам;
  `isPreset` означает источник seed, а не неприкосновенность.
- **BR-CAT-7.** Любая активная категория расхода применима к квартире; отдельной
  иерархии/жёсткой привязки нет.
- **BR-CAT-8.** Архивная категория недоступна для новых операций, но отображается в
  старых записях и фильтрах с пометкой «Архивная».

## 12. Резервное копирование и обновления (BR-BU / BR-UP)

- **BR-BU-1.** Экспорт создаёт consistent SQLite snapshot через `VACUUM INTO`; рабочая БД
  остаётся открытой. Доступны системный share и выбор destination через SAF/file picker.
- **BR-BU-2.** Импорт требует явного destructive confirmation и проходит magic bytes,
  integrity, application identity, schema version и foreign key validation до закрытия
  текущей БД. Backup другого приложения не принимается.
- **BR-BU-3.** Схема новее установленной отклоняется; поддерживаемая старая схема
  мигрируется на candidate, а не на единственной production-копии.
- **BR-BU-4.** Перед заменой создаётся rollback snapshot. Сбой rename/reopen/rebuild
  восстанавливает прежнюю БД и DI; ни один путь не удаляет единственную рабочую копию.
- **BR-BU-5.** Успешный импорт пересоздаёт DI/router/app tree и все активные streams.
  Повторные backup actions во время busy запрещены; picker/save cancel не является ошибкой.
- **BR-BU-6.** Backup содержит финансовые данные без шифрования. UI предупреждает об этом,
  не обещает облачную синхронизацию и не запрашивает broad storage permissions.
- **BR-UP-1.** Обновление проверяется только по кнопке через GitHub Releases репозитория
  `garryk3/finanseapp`; offline не мешает локальному приложению.
- **BR-UP-2.** Сравниваются numeric semantic versions; malformed version/response даёт
  checkFailed. Открываются только HTTPS APK или release page, установка выполняется ОС.
- **BR-UP-3.** При ошибке APK предпринимается fallback на release page. Невозможность
  открыть обе ссылки, отсутствие релизов и актуальная версия имеют разные статусы.

## 13. Seed-данные

Валюты: RUB, CNY, EUR, USD, HKD, все с `fractionDigits = 2`.

Доходы: Зарплата; Аренда; Проценты по вкладу; Дивиденды; Подарки; Прочие доходы.

Расходы: Питание; Аренда жилья; Содержание помещения; Коммунальные платежи; Ремонт;
Налоги; Транспорт; Здоровье; Развлечения; Прочие расходы.

Seed выполняется только при создании БД и защищён уникальными ключами. Повторный запуск
не дублирует записи и не восстанавливает изменённые пользователем названия.
