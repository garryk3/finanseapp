Вы - эксперт по управлению проектами и код-ревью. Ваша задача - проверить файл PLAN.md перед релизом.

**Шаг 0:** прочитайте `docs/REPO_CONTEXT.md` (протоколы трекеров). Терминология: `PLAN.md` — живой трекер («Индекс этапов» + текущий этап), небольшой — читайте целиком; завершённые этапы — в `PLAN_ARCHIVE.md`; стабильный техконтекст — `docs/PROJECT.md`. Каждый пункт плана должен быть чётким, выполнимым и синхронизированным с кодом.

## Что проверять

### 1. Структура и форматирование
- [ ] Все пункты пронумерованы корректно; чёткая иерархия (задачи → подзадачи)
- [ ] Единообразное форматирование (чекбоксы, отступы); нет дубликатов

### 2. Содержательность
- [ ] Каждый пункт конкретен и измерим; атомарные шаги
- [ ] Критерии завершения; сложные задачи декомпозированы

### 3. Синхронизация с кодом
- [ ] Выполненные пункты отмечены `[x]`; новые изменения кода отражены
- [ ] Удалённый/изменённый функционал обновлён в описании

### 4. Актуальность и компакция
- [ ] План соответствует текущему состоянию проекта
- [ ] «Индекс этапов» полон, нумерация не ломает продолжение
- [ ] Завершённые этапы не дублируются в `PLAN.md` и `PLAN_ARCHIVE.md` одновременно
- [ ] Приоритеты логичны, зависимости ясны

### 5. Качество формулировок
- [ ] Активные глаголы («Реализовать», «Добавить», «Протестировать»); без двусмысленности
- [ ] Технические термины корректны; объём задач реалистичен

## Процесс проверки

1. Прочитайте текущий `PLAN.md` (индекс + текущий этап); при необходимости сверьтесь с `PLAN_ARCHIVE.md` (только нужные секции, `grep -n`).
2. Соберите релизный дифф: `git diff origin/main...release/<NN>` и `git diff --name-status origin/main...release/<NN>` (generated-файлы — `*.g.dart`, `lib/l10n/app_localizations*.dart`, `test/generated_migrations/**`, `drift_schemas/**` — вне области).
3. Сравните изменения кода с обновлениями в PLAN.md; выявите несоответствия.
